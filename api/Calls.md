# Calls (Audio / Video)

Status: audio calls implemented (client-to-client). Video is planned.

## Principle

No direct contact attempt between peers - direct connections harm privacy. A
call is negotiated through ordinary E2E messaging and the media is carried over a
one-time hidden-network tunnel, so no server or facade ever sees call traffic.

## Transport

Media rides **SAM v3 RAW datagrams** (UDP-like, low overhead) over I2P, one
short-lived destination per call, torn down when the call ends. RAW carries no
per-packet source (so an audio frame stays small) and no I2P-layer
authentication - the call layer authenticates every datagram itself (see Media
encryption).

The call's media destination publishes an **encrypted LeaseSet2 (b33)**, like
every other Bazarish destination. This requires a SAM bridge that routes
datagrams to blinded (b33) addresses: stock i2pd routes SAM datagrams only by
identity hash, so datagram-to-b33 is an i2pd change (submitted upstream).
Without it the media never arrives. The destination is one-time and torn down
with the call, and its b33 routing address is shared only with the peer inside
the E2E-encrypted invite.

A SAM STREAM channel may be added later for in-call service messages; the audio
itself stays on datagrams.

## Codec

Opus, 48 kHz mono, 20 ms frames (the standard VoIP trade-off). Lost frames are
concealed by Opus; late or duplicate frames are dropped.

## Media encryption

The I2P tunnel encrypts the transport, but media is additionally protected
end-to-end, independent of the transport, with **AES-256-GCM** (a standard
primitive; no custom construction). The 32-byte key is generated by the caller
and carried in the call.invite, which is itself E2E-encrypted to the peer, so the
key never reaches any server. Each datagram is `nonce || AES-256-GCM(opus)`,
where the 12-byte nonce is `role || sequence`: the role byte separates the two
call directions and the per-sender monotonic sequence guarantees a (key, nonce)
pair is never reused. A forged, replayed or wrong-key datagram fails to open and
is silently dropped.

## Strict SAM requirement

A call is impossible without a local I2P SAM bridge. Placing a call
(startAudioCall) or accepting one (acceptCall) probes the bridge first and, if
none is reachable, fails immediately with the typed, readable error
`SAM_UNAVAILABLE` - no call is placed and nothing half-starts.

## Signaling message types

Call signaling is ordinary Layer-2 content (see `../Messages.md`): each signal is
a `content`-class delivery whose end-to-end payload carries the `call.*` type.
Server-side components see only opaque blobs of a generic message.

| Type | Direction | Payload |
|---|---|---|
| `call.invite` | caller -> callee | `callId`, `media` (`audio`), `codec` (`opus`), `dest` (the caller's media b33 routing address), `key` (base64 per-call media key) |
| `call.accept` | callee -> caller | `callId`, `dest` (the callee's media b33 routing address) |
| `call.decline` | callee -> caller | `callId`, `reason` (`declined` / `busy`) |
| `call.end` | either | `callId` |

Adding or evolving a call signal is a client-only change.

## Flow (audio, I2P)

1. **Caller** builds a one-time RAW datagram destination via the SAM bridge
   (strict: no bridge -> `SAM_UNAVAILABLE`), generates a per-call AES key, and
   sends a `call.invite` carrying its media b33 and the key over the normal E2E
   delivery path.
2. **Callee** receives the invite (on sync) and rings. On accept it builds its
   own RAW datagram destination and replies with `call.accept` carrying its
   media b33.
3. Both sides now know each other's media destination and the shared key. Each
   captures the microphone, encodes Opus, AES-256-GCM-seals it and sends
   datagrams to the peer's b33; received datagrams are opened, decoded and
   played. Mute simply stops transmitting.
4. Either side hangs up with `call.end`; the media engine and the one-time
   datagram destination are torn down.

## Implementation

- **common**: `SamDatagramSession` (SAM v3 RAW datagram transport) and
  `aeadSeal`/`aeadOpen` (AES-256-GCM).
- **client lib**: `AudioCodec` (Opus), `AudioIo` (device interface + a synthetic
  backend), `CallMedia` (the two-thread capture/playback engine), and the call
  signaling + state machine on `Session` (`startAudioCall` / `acceptCall` /
  `declineCall` / `endCall` / `setCallMuted` / `currentCall`).
- **CLI**: `bazarish-client call` and `call-answer` (drive the signaling loop;
  used for integration testing of the transport).
- **GUI**: `CallScreen.qml` plus a Qt Multimedia (`QAudioSource`/`QAudioSink`)
  audio backend.

Live-validated: SAM RAW datagrams round-trip over real I2P between two
destinations. The codec round trip, the AES-256-GCM seal/open (including
tamper/wrong-key rejection), and the full media pipeline over an in-memory
loopback are covered by unit tests.

Needs i2pd with a SAM bridge, its datagram UDP port (default 7655) reachable,
and SAM datagram-to-b33 routing (an i2pd change submitted upstream; until it is
released the local router must carry the patch).

## Open / not done

- **Video** - the signaling negotiates `media`, but only `audio` is implemented.
- **Jitter buffer** - playback is in-order with bounded packet-loss concealment;
  a deeper adaptive jitter buffer is a refinement.
- **Glare / busy** - a second incoming call while busy is auto-declined with
  `reason: busy`; richer call-waiting is future work.
